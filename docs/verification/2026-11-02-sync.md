# Sync verification

November 2, 2026, on `feat/sync-dropbox` (#12, PR #36). The CI job **Duo sheet and sync captures** took these in [run 41475015811](https://github.com/millZach/Vellum/actions/runs/41475015811) at commit c352adc, on GitHub's hosted `xcode-27` image with Xcode 27.2 and the iPhone Duo simulator (iOS 27.1), unfolded by `apps/ios/Scripts/capture-duo.sh` (`sync_captures`). Each capture is 2853 × 2007 pixels, which is 951 × 669 points at 3×. The simulator has no Dropbox key, so the app syncs to VellumCore's made-up Dropbox (`MadeUpDropbox`, in memory) behind the same transport seam the live client uses (`--ui-sync`, `apps/ios/Vellum/DebugSync.swift`). The canvases are the made-up fixtures, with no real drawing in them.

## Airplane mode, then the connection back (the test #12 names)

`--ui-sync airplane`:

1. The made-up Dropbox is switched off, and the sync engine is told the Duo is offline. The app makes "Airplane mode test (example)" and commits the fixture's 17 strokes through the canvas screen. `unfolded-sync-airplane-canvas-offline-light`: the status bar reads "Saved · offline" in amber, with "Draw with the Pencil" in full.
2. Leaving the canvas queues it. `unfolded-sync-airplane-list-offline-light`: the list says "Offline. 1 canvas isn't in Dropbox yet…", and the row reads "waiting for Dropbox". The made-up Dropbox holds 0 files.
3. The Dropbox comes back and the engine is told the Duo is online: the outbox goes at once. `unfolded-sync-airplane-list-online-light`: no banner, the row has no note. 2 requests, 2,182 bytes.
4. The laptop's view: the made-up Dropbox's `Vellum/Airplane mode test (example) 6baf/` holds `canvas.json` (235 bytes) and `ink.log.parts/0/000000000000.part` (1,947 bytes). Rebuilt by the rule in ADR-0014's #12 amendment (`SyncedCanvasFolder`), `canvas.json`, `ink.snapshot` (none on either side) and `ink.log` match the Duo's byte for byte, and the rebuilt canvas opens with all 17 strokes. The job log and `sync-airplane.txt` in the artifact give each step.

## Each state, in light and dark

`unfolded-sync-<state>-<light|dark>` is the fixture canvas, `unfolded-sync-list-<state>-<light|dark>` the four made-up canvases of the list:

- `synced`: "Synced to Dropbox", in grey; no notes in the list.
- `offline`: the canvas edited offline, "Saved · offline" in amber, tinted, with its warning sign; the list's amber banner, and "waiting for Dropbox" on each row.
- `failed`: "Sync failed" with a small Retry; the list's banner names the canvas that failed and has Retry, and its row reads "sync failed · will retry". The canvases behind it in the outbox read "waiting to sync".
- `signedout`: "Signed out" with a small Sign in; the list's banner says "Dropbox signed out…" with Sign in, and each row "Dropbox signed out".
- `notsaved`: for contrast, "Not saved: will retry" in amber on a synced canvas; in the list the existing "is not fully saved yet" banner. The wording there never starts "Saved", and the offline wording always does.

In every status bar capture the tool prompt "Draw with the Pencil" is in full; `SyncStatusLineTests` holds the sync wording to the length of "Saved on this Duo", which it replaces, so every 28-character prompt keeps its room.

## Not checked here

- A real Dropbox. The made-up one answers as Dropbox's documented API does (ADR-0013's #12 amendment); the first sync against the real one is the TestFlight test above.
- Background time. The simulator's captures never go to the background; `CanvasSync.setInBackground` is covered by `SyncTests`, and iOS's background-task limit by the Duo test.
- A file changed in Dropbox underneath: `SyncTests` covers it (the Duo's copy replaces it, noted in the ledger); there is no screen for it.
